# `portal_finance` — контрагенты, договоры, счета, платежи, закупки

> **Статус UI:** временно заморожен (пункт меню и SPA-маршрут `/finance` скрыты). API и SQLAdmin сохранены — не удалять пакет без решения о разморозке.

## Назначение

Пакет закрывает финансовый и закупочный контура портала: справочник контрагентов, договоры, счета (акты), привязанные платежи, закупочные заявки. **Не** отвечает за расчёт зарплаты, бухучёт вне портала и внешние ERP: только данные, которые хранятся в БД портала и отдаются через API и SQLAdmin.

**Сквозная политика доступа** (rate limiting на периметре и т.п.) описана в [../MODULES.md](../MODULES.md) — в этом README — только нюансы домена `portal_finance`. Финансовые сущности домена (договоры, счета, закупочные заявки, платежи) — **глобально видимы** всем авторизованным пользователям портала: концепция «разделов навигации» (`nav_node_id`) и связанной RBAC-фильтрации из домена полностью удалена.

## HTTP

Роутер: [`router.py`](router.py), префикс **`/portal/finance`**. Подключается в [../api/v1/router.py](../api/v1/router.py) к общему `APIRouter` приложения, базовый префикс API — `/api/v1` (см. [`main.py`](../main.py)).

Типовые пути: `/api/v1/portal/finance/counterparties`, `.../contracts`, `.../invoices`, `.../payments`, `.../procurement`.

**OpenAPI теги:** `Финансы · Контрагенты`, `Финансы · Договоры`, `Финансы · Счета и акты`, `Финансы · Платежи`, `Финансы · Отчёты`, `Закупки · Заявки`.

## Карта пакета

| Путь | Содержимое |
|------|------------|
| `routes/counterparties.py` | CRUD-список контрагентов (создание/изменение — с ограничениями для не-админов) |
| `routes/contracts.py` | Договоры, soft-delete |
| `routes/invoices.py` | Счета; при указании `contract_id` — проверка доступа к договору через сервис |
| `routes/payments.py` | Платежи, агрегат `/summary` |
| `routes/procurement.py` | Закупочные заявки |
| `services/counterparty.py` | Список/мутации контрагентов, гарды `portal_admin` на запись где нужно |
| `services/contract.py` | Договоры, CRUD, soft-delete |
| `services/invoice.py` | Счета; `get_contract(...)` при привязке/смене договора, чтобы не допустить IDOR |
| `services/payment.py` | Платежи по договорам/счетам, сводка |
| `services/procurement.py` | Статусы заявок; создание — только с ролью «Закупщик» или `portal_admin` |
| `schemas/*` | Pydantic: контрагент, договор, счёт, платёж, заявка |
| `admin/*.py` | SQLAdmin-вьюхи по сущностям: контрагент, договор, счёт, платёж, заявка |

ORM: [`infrastructure/db/models/portal_finance.py`](../infrastructure/db/models/portal_finance.py) (и связанные импорты в `admin/`).

## Сущности и права (сжатая карта)

| Сущность | Ключевой контур |
|----------|-----------------|
| Контрагент | Чтение/фильтра по активности; изменение справочника — в основном **админ**; см. сервис |
| Договор, счёт | Видны всем авторизованным; изменение — автор или `portal_admin` (см. `services/contract`, `services/invoice`) |
| Платёж | Видны всем авторизованным; удаление — автор или `portal_admin` |
| Закупка | Создание — роль «Закупщик» или `portal_admin`; статусы в `app.core.enums` |

Инвариант: **счёт** не должен ссылаться на **чужой/недоступный договор** — при `contract_id` вызывается `get_contract`, чтобы согласовать с правилами договора (в т.ч. после смен `owner_sub` / админ-логики).
