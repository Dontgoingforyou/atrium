# Atrium — требования

## В двух словах

Портал: вход, задачи, документы, чаты, календарь, поиск, специалисты, аналитика и таймшиты. Доступ только после авторизации; права разграничены (RBAC).

Разделы **Договорённости**, **Финансы** и **Обучение** временно скрыты в UI (код сохранён) — в FR ниже не входят как Must.

## Связь с экранами

Реестр: [screens-index.md](./screens-index.md). Канон UI — React SPA (`frontend/src`).

## Требования

### FR-001: Вход

**Экран:** login  
**Роли:** anonymous, user  
**Приоритет:** Must

Пользователь открывает `/login`, вводит логин и пароль и попадает в портал: access token в памяти SPA, refresh — в httpOnly cookie. Демо-учётки перечислены на форме.

---

### FR-002: Тихий refresh сессии

**Экран:** app-shell  
**Роли:** user  
**Приоритет:** Must

После перезагрузки SPA access token восстанавливается через refresh cookie без повторного логина, пока cookie валиден.

---

### FR-003: Главная

**Экран:** home  
**Роли:** user  
**Приоритет:** Must

Авторизованный сотрудник (не student) видит сводку главной страницы портала.

---

### FR-004: Задачи — список и создание

**Экран:** tasks  
**Роли:** user  
**Приоритет:** Must

Пользователь открывает `/tasks`, видит доступные задачи и создаёт новую на `/tasks/new` в рамках RBAC.

---

### FR-005: Задачи — карточка

**Экран:** task-detail  
**Роли:** user  
**Приоритет:** Must

Пользователь открывает задачу по id или номеру (`/tasks/:taskId`, `/tasks/task-:taskNumber`) и видит детали, если есть право на чтение.

---

### FR-006: Документы портала

**Экран:** document  
**Роли:** user  
**Приоритет:** Must

Пользователь открывает документ (`/documents/:documentId` или `/p/:slug/documents/:documentId`) только при праве на чтение.

---

### FR-007: Чаты

**Экран:** chats  
**Роли:** user  
**Приоритет:** Must

Пользователь открывает `/chats`, видит свои чаты и обменивается сообщениями (HTTP и realtime).

---

### FR-008: Календарь и приглашения

**Экран:** calendar  
**Роли:** user  
**Приоритет:** Must

Пользователь работает с `/calendar` и принимает приглашение по `/calendar/invite/:token`.

---

### FR-009: Глобальный поиск

**Экран:** search  
**Роли:** user  
**Приоритет:** Must

Поиск на `/search` не возвращает сущности вне контура прав пользователя.

---

### FR-010: Специалисты

**Экран:** specialists  
**Роли:** user  
**Приоритет:** Must

Каталог специалистов на `/specialists` с просмотром в рамках RBAC.

---

### FR-011: Аналитика и таймшиты

**Экран:** analytics  
**Роли:** user, student  
**Приоритет:** Must

Раздел `/analytics` (сводка, отчёты, таймшиты). Студенты попадают в контур таймшитов по правилам маршрутизации SPA.

---

### FR-012: Теги

**Экран:** tags  
**Роли:** user  
**Приоритет:** Should

Просмотр и управление тегами на `/tags`.

---

### FR-013: Настройки аккаунта

**Экран:** account  
**Роли:** user  
**Приоритет:** Must

На `/account` пользователь видит и меняет настройки своего профиля.

---

### FR-014: Мост в SQLAdmin

**Экран:** admin-bridge  
**Роли:** admin  
**Приоритет:** Must

Администратор открывает `/admin` через `/admin-bridge`; без роли admin доступ закрыт.

**Экран:** trash  
**Роли:** manager, admin

### FR-016: Health API

**Экран:** n/a  
**Роли:** system  
**Приоритет:** Must

`GET /api/v1/health` отвечает 200, пока процесс API жив.

---

### FR-017: Guided tour (онбординг UI)

**Экран:** app-shell  
**Роли:** user (полный контур); timesheet-only (ограниченная роль / students — отдельный учёт времени)  
**Приоритет:** Must

Интерактивный guided tour по живому SPA: spotlight + tooltip, переходы между разделами, без отдельной страницы-руководства и без модуля Learning.

- Автостарт при `guided_tour_completed=false` (preferences в portal-core) — для всех авторизованных ролей, включая timesheet-only.
- Шаги привязаны к реальным элементам UI; отсутствующий target — skip.
- Во время тура не создавать и не изменять пользовательские данные (учёт времени — только учебные записи таймшита и документ с `is_tour_demo`, удаляются по завершении тура).
- Role-aware: недоступные разделы/элементы исключаются из последовательности.
- Повторный запуск: regular/manager/admin — из `/account` («Пройти обучение заново»); timesheet-only — кнопка «Обучение» в боковом меню (страницы «Аккаунт» нет).

**MVP (Must):** shell (поиск, расширенный поиск, уведомления, тема), главная, задачи (канбан + форма создания; у manager/admin — walkthrough полей формы и секций карточки учебной задачи: подзадачи, комментарии, ссылки, файлы), аккаунт + финал.
**Should:** специалисты, чаты (список, ПКМ, сообщения, ответы/реакции, ввод), календарь, теги, аналитика (сводка/таймшиты/отчёты), корзина, админка (nav), документация (nav + открытие документа: заголовок, теги, тело, комментарии).
**Timesheet-only (Must):** тема, навигация таймшитов, действия/фильтры/вкладки/записи/отчёт, developer-docs (заголовок, тело, комментарии — просмотр), кнопка «Обучение» + финал.

---

### FR-018: Что нового

**Экран:** changelog  
**Роли:** user  
**Приоритет:** Must

Авторизованный сотрудник (не student и не timesheet-only) открывает «Что нового» иконкой в шапке, слева от смены темы. Список — модалка. Пока этот сотрудник не открыл последний патч, на иконке горит кружок. Сначала 10 записей, дальше подгрузка предыдущих по 10.

## Нефункциональные требования

| ID | Текст |
|----|-------|
| NFR-001 | Datetime в бизнес-логике — aware UTC |
| NFR-002 | Любая выборка с данными учитывает RBAC (в т.ч. поиск) |
| NFR-003 | Refresh только в httpOnly cookie; access token не в localStorage |
| NFR-004 | Портал закрыт: без авторизации UI и API недоступны |
